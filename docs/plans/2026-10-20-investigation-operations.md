## Design

- Keep the existing planner schema/policy and four algorithms compatible. Add comparison helpers and a separate versioned decision-journal schema.
- Active selection lives in a small browser-memory external store, survives route changes, and is hidden when its snapshot, archive or normalized input differs. Saved reviewer history lives in a bounded private JSON file beside existing audit state, deduplicating report payloads.
- The map adds one unclustered ring layer for at most 50 planned sources. No new shader, animation, imagery requests or heavier terrain settings.
- An imported prior export requires a separately supplied expected digest. Both inputs replay before comparison. Historical snapshots already listed in metadata are not sufficient to fabricate per-source changes; real earlier inputs must be available or imported.
- Current evidence auditing remains available from each queued source. AI credentials and model calls remain backend-only; an unavailable live provider stays explicitly unavailable. Human plan acceptance is not acceptance of a mitigation claim.

## Limits

No calibrated investigation value, estimated avoided emissions, measured user benefit, live AI quality, future snapshot acquisition or public-chain proof is promised by this increment. Reviewer attestation follows existing operator enrollment, not independent identity certification. Local files require backup and one writer; ephemeral previews are not durable hosting.

## Implementation review disposition

- Stale activation after changing strategy: activation generation and strategy/context key checked after replay; delayed-browser replay regression added.
- Restored report under a different visible country: restore requires matching scope, snapshot, archive and normalized input; browser scope-handoff and input-binding regressions added.
- Draft recovery shared between reviewer identities: reviewer ID included in recovery key and editor remount; browser disconnect/reconnect test added. This is not strong SessionStorage isolation.
- Overlapping source/plume/footprint click handlers: one global dispatcher chooses one target by explicit layer priority, with helper regression covering linked/unlinked overlaps and repeated originalEvent.
- Form labels after repeated editing: explicit accessible labels on allocation/rationale; reviewer browser scenario includes repeated edits and a real API CAS conflict.

Read-only follow-up review found no remaining actionable issue in the reviewed activation, scope, recovery and click-wiring boundaries.
