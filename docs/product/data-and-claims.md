Reproduce this read-only freshness check with `python services/data-pipeline/check_mars_upstream.py`. The reproducible check run on 2026-10-15 returned `unchanged` for both archives.

For a direct byte-level recheck, run `python services/data-pipeline/check_mars_upstream.py --verify-content`. This downloads each archive as a stream, retains only a bounded chunk in memory, and compares SHA-256, byte length, and `Content-MD5` to the pinned snapshot. The default per-archive limit is 256 MiB and can be lowered with `--max-content-bytes`; exceeding it returns `unavailable`. The command does not write the downloaded archives, parse them, or change/promote any snapshot. This is an optional read-only transfer of about 66 MiB for the currently pinned pair; the default metadata-only command remains fast and downloads no archive bytes.

The two CSV tables have different meanings:

- `source_name` is the documented source identifier; `id_plume` is the unique observation identifier. Keep their relation explicit; never derive an ID from a display name or location.
- Source-level `feedback`, `feedback_operator`, and `feedback_government` indicate receipt status for a source. They do not contain the response documents or prove that physical mitigation was completed.
- Plume-level and source-level `notified` values are retained in their original scopes. A source flag does not identify the recipient or exact notification time and cannot alone support an `operator_notified` audit.
- A row without `source_name` remains an unlinked observation. It is excluded from source-specific casebooks rather than assigned to a guessed facility.

Reproduce the import and browser projection using the commands in `data/real/README.md`. Synthetic fixtures are available through a separate mode for rule testing.

The optional **MARS publisher geometry** map layer uses the official GeoJSON archive matched one-to-one to the pinned CSV snapshot by plume ID. The October 14 archive contains 30,414 plume records: 29,207 publisher geometries and 1,207 records for which the publisher supplied no geometry. See [`MARS_PUBLISHER_GEOMETRY.md`](../architecture/mars-publisher-geometry.md) for hashes, monthly lazy loading, license, color scale, and validation. Geometry is not an interpolated methane concentration field or independent proof of a physical plume boundary; absent geometries remain absent. This historical layer does not imply live monitoring.

The Evidence Auditor can request the selected observation's publisher geometry from its shared monthly shard. The browser verifies the pinned geometry index, CSV snapshot/archive binding, compressed shard hash, and exact plume ID/source ID/date/coordinates/flux/uncertainty before displaying the outline. In particular, the AIRS 400 hPa layer is an upper-atmosphere product and must not be interpreted as a local surface leak or a methane plume measurement. ## Data handling

1. Download real snapshots manually, recording URL, retrieval timestamp, source license, and SHA-256.
2. Store raw downloads under `data/raw/`, excluded from Git.
3. Parse with explicit source ID mapping; a plume ID is not the same as a persistent source ID.
4. Never treat UNEP's source-level `feedback` as per-plume evidence of repair.
5. Non-observation by a satellite is not proof that emissions ceased. Consider revisit interval, cloud/sensor limits and uncertainty.
6. Do not claim UNEP endorsement. Distinguish UNEP's official confirmations from independent algorithmic conclusions.
7. Case report PDFs may have different licenses: link to source rather than rehost/adapt until permissions are confirmed.
8. For later commercialization, obtain suitable data rights; a hackathon demo does not imply a commercial license.

## Supported claims

- `source_detected`: at least one traceable detection record.
- `operator_notified`: a traceable record of communication to an operator.
- `mitigation_confirmed`: a traceable confirmation report; **not** just feedback or missing plume.

The evidence baseline supports three outputs: `supported`, `insufficient_evidence`, `contradicted`. `supported` always means *supported by the provided evidence*, not that the evidence itself is authoritative or physically proven. The source-level MARS `notified` field is displayed as metadata, not as evidence that a specific operator was notified. The 15-claim rules-conformance benchmark remains pinned to the October 14 three-source casebook; detection observations can be cited there, while operator-specific notification and mitigation claims abstain because supporting records have not been included and reviewed. The active October 15 casebook adds the Canada publisher link but does not add its report content to that benchmark or assessment input.

## Submitted-document rights declarations

Every document sent to the configured AI assessment endpoint must include a per-document `rightsDeclared` value: `owned`, `explicit_permission`, or `open_license`. The open-license path additionally requires a source URL, license name, HTTPS license deed, attribution, and explicit confirmation that the declared license scope and provider terms allow excerpt processing and private quote retention. This metadata is included in the versioned audit digest and shown beside the submitted document in the reviewer report. Historical bundles without this metadata remain verifiable and are displayed as having no rights declaration recorded. These are submitter declarations; they do not independently establish copyright ownership, legal permission, license applicability, source authenticity, completeness, or scientific validity. Consent to external processing and consent to publish citations remain separate decisions. The preparation tool parses and packages excerpts locally; it does not contact the source or an AI provider.

## Investigation intelligence snapshot

`services/data-pipeline/build_intelligence.py` derives `data/processed/intelligence-snapshot.json` from the full pinned browser dataset at `apps/web/public/data/mars-snapshot.json.gz`. Its source/plume join uses only each plume's explicit linked `sourceId`; missing or unknown IDs are not assigned. The active snapshot covers all 4,218 MARS source rows and 23,861 explicitly linked plume observations in release `unep-mars-675417694883`, from 2020-10-29 through 2026-09-13. It stores the compressed input SHA-256 `f27c21ab0932de3768a57029410c90677944e732f8be341e1d3abf4f36a91ae7`, source archive hash, dataset ID, publisher, license, catalog URL and attribution, identifiers, timestamps, numeric/missing flux counts, uncertainty summaries, publisher-indicator context and heuristic components. Re-running the builder with unchanged gzip bytes produces the same output and uses the recorded retrieval timestamp, not the current clock.

The investigation score is a bounded heuristic based on distinct observation dates and median numeric observed flux. A source with missing flux has a null magnitude contribution; it receives no fabricated zero-flux measurement. Source persistency and emission-status fields are displayed for context but are not treated as a future outcome label. The API verifies the intelligence snapshot against the exact pinned browser bundle and its upstream archive identity, and serves an insight only when the source ID exists in that snapshot. A forecast of future physical methane emissions remains `not_available`: the archive does not provide complete per-source sensor opportunities or independent physical-emission outcomes.

Schema v2 (`transparent-priority-v4`) adds `theil-sen-event-trend-v1`: numeric plume fluxes are reduced to a median for each UTC observation date, then the median of all pairwise slopes is expressed as kg/h change per 30 days. A descriptive slope is emitted only when at least four distinct numeric-flux dates span 90 days. The API binds the summary to the pinned browser bundle; the selected-source UI builds the scatter plot from those same raw observations and hides it if the dates or endpoint medians do not match. Points remain separate, with no interpolation between detections. The reported uncertainty summary is not a prediction interval, positive-slope share is not confidence, and none of this estimates future emissions. In the pinned October 14 snapshot, 1,259 sources meet the descriptive-data threshold, 60 have enough dates but insufficient span, and 2,899 have too few numeric dates. These counts describe input sufficiency, not forecast coverage, predictive accuracy, or leak outcomes.

Schema v3 (`transparent-priority-v5`) adds a separate logistic model, `mars-linked-record-recurrence-logistic-v1`. Its target is specifically whether a source already present in the archive receives at least one additional **linked MARS detection record** during the next 365 days. It does not predict methane presence, future flux, an active leak, mitigation, or sensor opportunity. The point-in-time features use linked detection dates known at the forecast origin: recent date count, cumulative date count, and days since the latest date. Training origins are 2021-09-11, 2022-09-11, and 2023-09-11; 2024-09-11 is reserved for Platt calibration; the retrospective final time window is 2025-09-11–2026-09-11. The report binds the fitted parameters, calibrator, predictions, evaluation metrics, and snapshot to the compressed browser input SHA-256 and snapshot ID. The prediction is suppressed unless the final horizon is complete, the 30-day release buffer passes, cohort sizes are adequate, and every evaluation gate passes.

On the pinned `unep-mars-675417694883` snapshot (last linked record 2026-09-13), the retrospective test cohort contains 3,131 known sources and 1,251 with another linked archive record in the target window (2025-09-11–2026-09-11). Results: ROC AUC 0.808101 (country-cluster bootstrap 95% CI 0.786658–0.827566); Brier score 0.181117 versus the calibration-prevalence reference 0.250427 (Brier skill 0.276768; bootstrap 95% lower bound 0.238889); ECE10 0.088180 (95% upper bound 0.140755); top-decile precision 0.866242 and lift 2.168× (95% intervals 0.800000–0.940439 and 1.833–2.585×). The simple recent-date-count baseline has ROC AUC 0.779053; paired country-cluster bootstrap AUC improvement is 0.020285–0.040533. Intervals use 79 country clusters, 400 fixed-seed replicates, seed 177. Source `DZA_S_012` has point estimate 0.918307 for the same archive-record target as of 2026-09-13; it is not a source-level confidence interval. Browser input SHA-256 is `f27c21ab0932de3768a57029410c90677944e732f8be341e1d3abf4f36a91ae7`; intelligence artifact SHA-256 is `40095bdf6963ab8f29f8188787de37e54620e7858d95982700a350187c1e7049`. The retrospective test window was inspected during development, so these numbers are neither prospective nor independent evidence and do not predict physical leakage. All release gates pass for this archive-record target only; MARS observation opportunity is incomplete and absence of a later row is not evidence of zero emissions. Reproduce with `cd services/data-pipeline && python build_intelligence.py`; run the data suite with `uv run pytest -q` from that directory.

To enable a future test without inspecting labels before registration, the workflow now freezes a v6 label-free ledger for all 4,218 sources in this snapshot. It binds source IDs, probabilities, the baseline, model/calibration specification, code hashes, cutoff (`2026-09-13`), input hashes, and future window ending `2027-09-13`. Freeze validates observation links and provenance, optimizer/calibrator metadata, parameter and metric domains, internal metric relationships, bootstrap seed and cluster counts, and gate calculations; it recomputes each source probability from frozen features and model parameters. The evaluator requires a different complete MARS snapshot retrieved at least 30 days after the window; backfills before the cutoff are ignored and absent sources remain unknown. The same-snapshot replay is explicitly `not_available` with zero labels. No prospective outcome has been observed. v5 and earlier ledgers remain historical; details and hashes are in [prospective recurrence registration](prospective-recurrence.md).

The same snapshot carries a separate `anomalyAnalysis` screen (`mad-threshold-screen-v1`). It requires at least eight numeric flux observations on four distinct dates. It uses 1.4826 × MAD as its robust scale, or the median positive reported uncertainty when MAD is zero, and flags only deviations above `max(3.5 × scale, 2 × that observation's reported uncertainty)`. Each candidate retains the plume ID, date, flux, uncertainty, deviation and threshold. Insufficient observation count or date coverage is explicit abstention; a result with no flagged candidate is not evidence of zero emissions. This screen is not independently validated and does not change the separate investigation-priority score. In the pinned 4,218-source release, 3,555 sources abstain for fewer than eight numeric observations, 2 for date coverage, 466 have no candidate above threshold, and 195 have one or more statistical candidates (294 candidate points total). These counts describe this fixed snapshot and algorithm only; they are not detector-accuracy measurements or verified leak events.

## Optional document assessment

The optional model path accepts a source in the validated full MARS snapshot or the curated compatibility casebook, plus a bounded excerpt. Before a provider call, the submitter must separately consent to external processing and declare per document that it is owned or explicitly permitted for processing. The declaration and document digest are recorded in the versioned report; this is self-attestation, not independent rights verification. The excerpt is sent only to the configured server-side provider, exact quote substrings are checked, and selected quotations/document digests are stored instead of the complete source text. This verifies quotation matching to the submitted text only; it cannot establish document authenticity, context, scientific sufficiency, rights ownership, or physical mitigation. The provider path has not been measured on an independently human-labeled dataset. No AI benchmark metrics are claimed.

Human review is a distinct authenticated step with separate approve, reject, and request-more-evidence dispositions; each creates a new v3 audit revision linked to the prior bundle hash. Requesting more evidence produces `insufficient_evidence` until the evidence is reassessed. The local file store now supports durable anchor intents and reconciliation behind explicit server opt-in, as documented in the [P2 runbook](../development/blockchain-recovery.md). This was verified on disposable Anvil chain 31337; a public Sepolia receipt is still unavailable. Private schema 4 and unreviewed schema 3 cannot be anchored. Neither reviewer approval nor a blockchain receipt proves methane repair. The v3 bundle binds MARS archive provenance, the source's plume IDs, model/prompt version, reviewer decision, and current intelligence snapshot hash when available. Existing v2 audit and receipt records remain supported.

## Manual assessment and public summary

Manual assessments without AI use an event/period scope and private schema 4. Reference metadata, determination, rationale, rules coverage, parent hash, reviewer/reference-check status, and consent are bound to the stored revision. Origin/digest checks do not authenticate a document or prove mitigation. The full bundle remains private; only an allowlisted field projection may be published with consent for that revision. See [trust and transparency](trust-and-transparency.md) for directory, revocation, and publication-limit policies.


## Assessment semantics after P4 remediation

- The new baseline evaluates only **reference metadata coverage**. The UI uses the labels required references present / contrary reference present / insufficient reference coverage; API result codes remain compatible. A fabricated document with plausible metadata may still pass coverage.
- Notification and mitigation claims now require scope; a recipient name is required for notification. Real pointers must use HTTPS without credentials; local fixtures are for DEMO only. Inspect the source to assess the content and measurement quality.
- Scope dates are inclusive UTC days. Offset timestamps are converted to UTC; MARS timestamps without offsets are treated as UTC. A publisher's publication date does not replace the action or follow-up date.
- New bundles store `assessmentSemantics` in the hash: metadata / human / model, with physical verification **not established by the application**. Reviewers attest that they performed their own inspection; the application does not certify identity, independence, or physical outcomes. Human review of model output remains model-based.
- Older bundles are not rewritten. Missing semantics are marked historical/inferred in the display; hashes and schema 1 public-summary payloads continue to match the original bytes.
